# Дәлел — ни одного балла без доказательства

Прототип Conversation Quality Analytics для Freedom Broker CQA Hackathon. Команда −60HZ.

## Что это

«Дәлел» оценивает работу оператора по чатам и звонкам на русском, казахском и английском языках по настраиваемому чек-листу (стартовая конфигурация — 8 критериев организаторов, `data/checklists/v1.json`). По каждому критерию система показывает ответ (Да / Нет / шкала / N/A), баллы, вес, объяснение и реплику-доказательство. Если действие пропущено, указывается проверенный участок разговора; при N/A — причина. Ссылка в обосновании ведёт к нужной реплике или фрагменту звонка, для звонков есть плеер записи.

Модель возвращает только ответы, цитаты и объяснения. Итог считает детерминированный движок (`cqa/engine.py`): вес × ответ / максимум шкалы, при N/A вес перераспределяется между применимыми критериями, грубое нарушение помечается отдельным флагом, округление — один раз, half-up до двух знаков. Пример: C1 Да, C2 N/A, C3 N/A, C4 15, C5 Да, C6 7, C7 Да → 55,5 / 65 × 100 = 85,38 (проверено движком). Каждая цитата проверяется на дословное совпадение с транскриптом; это подтверждает источник, но не правильность интерпретации модели. Оператор может оспорить критерий, проверяющий подтверждает или меняет оценку с причиной, итог пересчитывается; исходная оценка ИИ и история решений хранятся отдельно.

## Шесть функций Student Guide → где в интерфейсе

Интерфейс — HTML/CSS/JS ES-модули без сборки, пять вкладок: «Диалоги», «Чек-лист», «На проверке», «Оценка», «Качество» (замеры с источником и полным знаменателем).

| # | Функция | Где |
|---|---|---|
| 1 | Создать чек-лист: критерии, формулировки, вес, тип ответа, N/A, шкала; сохранить конфигурацию | вкладка «Чек-лист»; каждое сохранение — новая версия, активируется после успешного прогона |
| 2 | Оценить выбранный диалог (загрузка транскрипта, выбор чек-листа, запуск; RU/KZ/EN) | вкладка «Оценка» (загрузка JSON или набор по `group_id`, выбор версии, модели: облако / каскад / локально) |
| 3 | Показать результат: ответ, баллы, вес, объяснение, реплика-доказательство, N/A, итог и секции | вкладка «Диалоги» → карточка диалога |
| 4 | Карточка: транскрипт, переход к реплике, прослушивание записи | вкладка «Диалоги» → клик по цитате; плеер у звонков |
| 5 | Подать апелляцию: критерий + комментарий | карточка диалога, роль «Оператор» |
| 6 | Решение проверяющего: подтвердить или изменить оценку с причиной, пересчёт итога | вкладка «На проверке» и карточка, роль «Проверяющий»; видны исходная оценка, решение и финал |

Контрольная замена критерия: «Чек-лист» → изменить или добавить критерий → сохранить → «Оценка» → применить версию к набору. Изменение веса пересчитывается без вызовов модели, замена формулировки переоценивает только изменённый критерий. Сценарий показа на 5 минут: [docs/DEMO_SCRIPT.md](docs/DEMO_SCRIPT.md).

## Запуск с нуля в 3 команды

Нужен Python 3.11+ (Node 20+ только для frontend-тестов). Ключи и данные для запуска в режиме `mock` не нужны.

```bash
python3.11 -m venv .venv && source .venv/bin/activate
pip install -r requirements-cqa.txt
CQA_PROFILE=mock python -m uvicorn server:app --host 127.0.0.1 --port 8000
```

Откройте http://localhost:8000 — страница сама подключается к серверу (демо-данные без сервера: `?mode=demo`). Проверка: `curl http://localhost:8000/api/health`. Профиль `mock` — тестовый оценщик с явной пометкой в интерфейсе; его оценки не измеряют качество модели. Для настоящей оценки задайте профиль (см. ниже). Данные и результаты хранятся в SQLite `results/cqa.sqlite` (путь — `CQA_DB`). Для проверки загрузите `eval/synthetic/records.json` (56 синтетических диалогов в формате API организаторов) на вкладке «Оценка». При загрузке укажите набор `SYNTH`, чтобы синтетика не смешалась с DEV организаторов.

## Данные: DEV и контрольный набор

Реальные диалоги организаторов в репозиторий не входят. Создайте `.env` в корне (в Git не попадает):

```dotenv
CQA_DATA_API=<ссылка GET из Student Guide без group_id>
CQA_PROFILE=cloud
CQA_BASE_URL=https://openrouter.ai/api/v1
CQA_API_KEY=<ключ OpenRouter>
# CQA_OLLAMA_URL=http://<машина с GPU>:11434   # для профиля local
```

```bash
python scripts/fetch_dataset.py DEV              # -> data/raw/dev_records.json (65 диалогов)
python scripts/fetch_dataset.py <group_id>       # контрольный набор -> data/raw/<group_id>_records.json
```

При первом старте сервер сам загружает `data/raw/dev_records.json`, если файл есть. Набор по `group_id` можно также запросить из вкладки «Оценка» (запрос идёт через сервер, CORS не мешает) или загрузить JSON-файлом.

## Прогон контроля

```bash
python scripts/control_run.py <group_id> --source api --version 1 --profile cloud --dry-run   # план без вызова модели
python scripts/control_run.py <group_id> --source api --version 1 --profile cloud             # живой расчёт, режим fast
python scripts/control_run.py <group_id> --source api --version 1 --profile cloud --ids <id1,id2>   # повтор упавших диалогов
python scripts/control_run.py DEV --limit 10 --profile mock --allow-mock                      # репетиция без сети
```

До старта скрипт печатает план: группу, число диалогов, версию и хеш чек-листа, названия критериев, профиль и модель.
Без `--version` берётся официальный чек-лист (v1), без `--profile` — профиль по умолчанию (`cloud`), а не последний выбор в интерфейсе.
Каждый диалог оценивается заново (без повторного использования ответов и кэша). Если у диалога не удался один критерий, экспортируются
ответы этого прогона, а пропавший критерий помечается ошибкой; прежние ответы никогда не выдаются за новые. Результаты:
`results/control_<group_id>.json`, `.csv` и `_trace.jsonl`; они же сразу видны в интерфейсе (фильтр группы). Каталог `results/` в Git не попадает.

## Как проверить процесс

- Оценка считается вживую: `control_run.py` оценивает каждый диалог заново, без кэша и прежних ответов; неудавшийся диалог экспортируется как ошибка.
- Диалог с уже существующим id из другой группы получает ключ `<id>@<group>`: наборы групп не смешиваются и фильтруются по группе.
- У каждой оценки есть трассировка (`results/control_<group_id>_trace.jsonl`): сырой ответ модели, версия промпта, токены, стоимость.
- Итог пересчитывает только детерминированный движок; вес меняется без вызова модели.

## Профили моделей

Задаются `CQA_PROFILE` или в `config/models.json`; `CQA_MODEL=provider:model` переопределяет основную модель.

| Профиль | Что это | Что нужно |
|---|---|---|
| `cloud` | **Gemini 4 Argon** через OpenRouter — основная модель; fast — 1 вызов на диалог (все критерии), accurate — 1 вызов на критерий (не замерен) | `CQA_API_KEY`, `CQA_BASE_URL` |
| `cascade` | Сначала **Claude Haiku 5.5**; если она пометила хоть один критерий «на проверку», весь диалог переоценивает Gemini 4 Argon | то же |
| `routing` | Политика банка: звонки сразу на **Gemini 4 Argon**; чаты начинает **Claude Haiku 5.5** и передаёт Gemini, если она пометила критерий «на проверку» или оператор работал с данными счёта клиента (C3) | то же |
| `local` | **qwen2.5:7b** через Ollama (ноутбук M4 16 ГБ, полностью офлайн; на GPU-сервере банка — модель крупнее); при сбое диалоги **не** уходят в облако | Ollama (`CQA_OLLAMA_URL`, по умолчанию localhost), загруженная модель |
| `claude` | Claude Sonnet через авторизованный `claude` CLI | установленный и авторизованный Claude CLI |
| `mock` | Тестовый оценщик без сети | ничего |

При отсутствии кредитов, лимитах или таймауте провайдера вызов переключается на запасную модель (`fallback` в конфигурации, по умолчанию `claude_cli:sonnet`); фактически ответившая модель записывается в трассировку и показывается в карточке. Неудачная реальная оценка никогда не подменяется мок-ответом.

### Качество, скорость и стоимость (замер 7 ноября)

Отложенная выборка — 21 диалог DEV (RU/KZ/EN, 2 звонка), 168 ячеек, правила оценки `m1-g9`; сравнение с машинным эталоном (159 ячеек с меткой). Выборка нужна для валидации модели и правил, а не как тест: по ней выбирали между вариантами правил. Совпадение с машинной разметкой на DEV — не независимая человеческая точность.

| Модель | Совпадение (ячейки с меткой) | Ошибка итога, баллов | Время на диалог (медиана) | $ на диалог |
|---|---|---|---|---|
| **Gemini 4 Argon** (`cloud`) | **152/159 (95.6%)** | 1.92 | 40 с (p95 49 с) | 0.0459 |
| Каскад Haiku → Gemini (`cascade`) | 152/159 (95.6%), на Gemini ушло 9 из 21 | 1.92 | 24 с (p95 116 с) | 0.0250 |
| Маршрутизация (`routing`): звонки → Gemini, чаты → Haiku с эскалацией при сомнении или работе с данными счёта | 152/159 (95.6%), на Gemini ушло 10 из 21 | 1.92 | — | 0.0261 |
| Claude Sonnet 5.5 | 147–151/159 (два прогона) | — | 18–23 с | 0.050 |
| Claude Haiku 5.5 | 147–152/159 (два прогона) | — | — | 0.005 |
| Qwen3.8-27B / DeepSeek V4 Pro / GPT-6.1 Terra | 147–148/159 | — | 31–150 с | 0.015–0.021 |

Ошибка итога — средняя абсолютная разница итоговых баллов с эталоном: 1.92 (14 из 21 диалога с полной разметкой). Каскад: медиана 24 с; звонки, ушедшие на Gemini, — до 2,5 мин.
Против полной машинной разметки gold_v2_full (все 21 диалог, спорная трактовка C7 «Завершение» в мягком прочтении): 85.1%, ошибка итога 10.19 — основная доля расхождений приходится на C7.
Профиль `routing` прогнан через оценщик продукта на тех же 21 диалогах; ответы моделей взяты из кэша идентичных вызовов, поэтому время в таблице не указано. Стоимость каскада и маршрутизации включает стадию Gemini по токенам × ценам конфигурации, в том числе для ответов из кэша.

**На 10 000 диалогов** (по $ на диалог, без накладных расходов): Gemini ≈ $459, каскад ≈ $250, маршрутизация ≈ $261. Каскад дешевле Gemini примерно в 1,8 раза; маршрутизация чуть дороже каскада, но отправляет все звонки и случаи с данными счёта сразу на сильную модель. Расчёт для банка — `docs/BANK_ECONOMICS.md`.

Почему основная модель — Gemini, а не Haiku: по точности они в пределах шума (Haiku — 147 и 152 в двух прогонах). Gemini выбрана за стабильность между прогонами и за C2, C4, C6; Haiku в 9 раз дешевле, поэтому она первая ступень каскада. Голосование 3–5 моделей точность не подняло. Из 7 оставшихся расхождений Gemini 4 приходятся на два звонка, в одном все модели ставят C1 «Нет» из-за искажённого распознаванием имени (эталон — «Да»).

**Охват по языкам и каналам (Gemini, против эталона):** EN 60/60, RU 75/77, **KZ 5/6 — в отложенной выборке один диалог (6 ячеек)**, **звонки 12/16 — два звонка (16 ячеек)**. Это слишком мало для вывода о точности на казахском и на звонках. Все прогоны — вкладка «Качество» (`web/data/quality.json`).

**Все казахские диалоги и все звонки DEV (Gemini, против эталона):** KZ — 15 чатов, **115/117 (98,3%)**; звонки — 5, **29/37 (78,4%)**: в звонках модель завышает шкалы C4 и C6, поэтому такие ответы чаще уходят на проверку человеку. 14 из 15 казахских диалогов входят в часть DEV, на которой настраивались правила оценки (на модели Haiku).

**Локальная модель без облака:** qwen2.5 7B (Ollama) на ноутбуке MacBook Air M4 16 ГБ, полностью офлайн — **99/159 (62,3%, 95% ДИ 56–69%)** на тех же 21 диалогах, в среднем 341 с на диалог, $0 за API. Это уровень черновика: локальный контур работает и данные не покидают машину, но для пилота нужна модель крупнее на GPU (qwen3.5 9B на RTX — план, не измерено).

**Устойчивость к пересказу:** пересказали 10 диалогов RU/EN/KZ другими словами (смысл и действия оператора те же) — Gemini дал тот же ответ в 79 из 80 ячеек; итог изменился у одного диалога из 10 (пограничная шкала C4). Выборка маленькая, звонков в ней нет.

**C7 — спорная трактовка.** Мы держимся буквы чек-листа: итог или предложение помощи И прощание. Две машинные разметки разошлись: при общем вопросе по тексту чек-листа судьи засчитывали голое прощание в 7 англоязычных чатах, при разборе по признакам — нет. Вопрос задан организаторам; смена трактовки — одна настройка без правки кода.

Фактические токены, ₸ и $ каждой оценки сохраняются в трассировке и показываются в `/api/health` (`cost_per_eval`) и `/api/metrics`.

## Архитектура

![Архитектура Дәлел](docs/architecture.svg)

Фронтенд (`web/`) → FastAPI (`api/`, `server.py`) → оценщик (`cqa/evaluator.py`: промпты, голоса, арбитр, проверка цитат) → провайдеры LLM (`cqa/llm.py`) и детерминированный движок (`cqa/engine.py`) → SQLite. Встраивание в Dynamics 365: [dynamics/README.md](dynamics/README.md), контракт — [docs/FRONTEND_HANDOFF.md](docs/FRONTEND_HANDOFF.md).

## Ограничения

- Точность не измерена против независимого человеческого эталона: цифры — совпадение с машинной разметкой на DEV. Методика: [docs/EVALUATION_PROTOCOL.md](docs/EVALUATION_PROTOCOL.md).
- Цитата проверяется на дословное совпадение; корректность вывода модели она не доказывает.
- Распознавание речи не выполняется: используются выданные транскрипты. Дикция и интонация не оцениваются.
- Нет авторизации (по условию задания): переключатель ролей оператор/проверяющий — демонстрационный. Для production нужны защита API, роли и политика хранения данных.
- Интеграция с Dynamics 365 показана локальным iframe-примером; в реальном tenant не проверялась.
- Качество и скорость зависят от выбранного провайдера. Локальная qwen2.5:7b на ноутбуке даёт 62,3% против 95,6% у Gemini на тех же 21 диалогах и ~6 мин на диалог; модель для GPU-сервера банка (qwen3.5:9b) не замерена.
- Не публикуйте `.env`, реальные диалоги, SQLite и трассировки.
