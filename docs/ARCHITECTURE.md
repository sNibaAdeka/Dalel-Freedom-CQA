# Архитектура Дәлел

Срез реализации: базовый commit `3515373`, 7 ноября 2026. Это текущий прототип; развёртывание в банковском контуре и Dynamics 365 требует отдельной проверки. Диаграмма — [architecture.svg](architecture.svg).

## От нового диалога к результату

1. **Данные.** Сервер принимает API набора или JSON. Нормализация сохраняет ID, язык, роли, текст и исходные таймкоды; бот и система остаются контекстом. Запись звонка открывается отдельно с учётом начала записи и пауз.
2. **План оценки.** FastAPI получает диалоги, версию чек-листа, режим и профиль. Новый диалог оценивается моделью по текущим правилам; повторное использование зависит от содержания критерия, версии промпта, режима и профиля.
3. **Вызов модели.** Fast запрашивает критерии пакетом. Исправление ответов, каскад и fallback могут добавить вызовы: fast не означает гарантированно один оплаченный вызов.
4. **Проверка.** Валидатор проверяет тип и шкалу ответа, допустимость N/A, существование реплики и цитату. Цитата может быть выровнена по исходному тексту с записью исправления; сохраняются реальные границы. Для пропущенного действия есть проверенный участок, для N/A — причина; валидная цитата не доказывает верный смысл.
5. **Расчёт и хранение.** Формула в коде превращает ответы в баллы. SQLite хранит диалоги, версии, оценки, апелляции, решения и прогоны. Решение проверяющего применяется к соответствующему правилу и пересчитывает итог, сохраняя исходный ответ.

## Формула находится в коде

Для применимых критериев с положительным весом:

```text
earned_i = weight_i × answer_fraction_i
answer_fraction_i = 1 для «Да», 0 для «Нет», value_i / max_scale_i для шкалы
total = round_half_up(100 × sum(earned_i) / sum(applicable_weight_i), 2)
```

N/A исключает вес из знаменателя. Если отсутствует ответ по весовому критерию, полного итога нет; если нет применимых весовых критериев, итог не рассчитывается. C8 имеет нулевой вес и отдельный флаг; отсутствие ответа C8 оставляет результат неполным, даже если численный итог остальных критериев доступен. LLM выбирает ответ и объяснение, а арифметику выполняет `cqa/engine.py` с точными дробями и half-up.

## Версии и живой расчёт

`criterion_hash` включает формулировку, тип ответа, шкалу, правила N/A, правила грубой ошибки и guidance. Вес и секция в хеш не входят: их изменение требует пересчёта формулы; изменение содержания — новой оценки критерия. Хеш здесь идентифицирует содержание, а не служит подписью или контролем доступа.

Создание версии и применение — отдельные действия. План показывает переиспользуемые и новые ответы; необработанным диалогам нужна полная оценка. `live=True` обходит кэш ответов для вычисляемых пар, сохраняя допустимые ответы неизменившихся критериев; `force=True` отключает и это переиспользование. В демонстрации необходимо назвать точный режим и показать счётчики.

## Dynamics 365

HTML/CSS/ES-модули находятся в `web/`. Host `dynamics/embed-demo.html` открывает iframe; bridge передаёт роль и ID диалога и получает уведомления о готовности, оценке, апелляции и решении. Проверяются точные `origin` и `source`, структура сообщений и разрешённый API; тексты диалогов и ключи в протокол не входят.

Это адаптация интерфейса, **не готовое внедрение в tenant**. Переключатель роли меняет UI и не заменяет серверную авторизацию; отдельно нужны вход, права, настройки origin/CORS/CSP, жизненный цикл данных и проверка в целевом окружении. Контракт: [dynamics/README.md](../dynamics/README.md).

## Границы качества

`web/data/quality.json` содержит источник, модель, выборку, пропуски, стоимость и признаки повторного использования DEV. Машинное совпадение на выборке, использованной для выбора модели, не является независимой человеческой точностью. Ограничения описаны в README; результат облачного Qwen3.8-27B нельзя переносить на локальную модель: локальная qwen2.5:7b замерена отдельно (62,3%).
