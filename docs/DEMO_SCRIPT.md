# Дәлел: защита за 5 минут

Сценарий следует странице 4 Student Guide: интерфейс → оценка и доказательства → апелляция → изменение критерия. Лимит — **300 секунд**, включая загрузки. Это план выступления, не отчёт о пройденной репетиции.

## Роли и подготовка

**Спикер** объясняет задачу и ограничения. **Демонстратор** управляет интерфейсом и вслух принимает роль проверяющего. **Таймкипер** подаёт сигналы на 1:00, 3:00, 4:00 и 4:45; в команде из двух человек это спикер с видимым таймером.

До выхода на сцену:

- Открыть окончательную сборку; записать commit, адрес, версию и профиль. `cloud / fast` означает настоящую модель; `mock` — проверку интерфейса на условных оценках.
- На контрольных данных заранее выполнить настоящий расчёт, как разрешает Student Guide. Сохранить ID прогона, модель, версию, фактические вызовы и результат. Контроль не заменять DEV-примерами.
- Из фактически завершённых оценок выбрать чат с цитатой и допустимым N/A, звонок с доступным аудио и обоснованный кейс апелляции. Записать ID на карточке демонстратора; не обещать заранее определённый ответ модели.
- Подготовить текст замены критерия и причину изменения. В защите заменить **формулировку**, а не только вес: это демонстрирует переоценку нового правила.
- Открыть звонок во второй вкладке, проверить звук и таймкод. Проверить проектор `P`, Safari и размеры 1280 / 1440 / 1920. Это пункты репетиции, не утверждение об уже выполненных проверках.
- Проверить локально сохранённый результат для аварийного показа. Если записано резервное видео, проверить воспроизведение без сети и записать путь; **наличие видео этим документом не подтверждено**.
- Репетиции интерфейса этой волны идут в mock; платные вызовы ради подготовки документов не запускаются. За живой финальный прогон отвечает команда релиза.

## Сценарий с секундомером

| Время | Кто и что нажимает | Реплика для жюри |
|---|---|---|
| **0:00–0:20** · 20 с | Спикер; демонстратор показывает «Диалоги» и версию | «Дәлел помогает проверить работу оператора: от настраиваемого правила до доказательства, апелляции и окончательного решения». |
| **0:20–1:00** · 40 с | Открыть выбранный диалог; показать язык, канал, транскрипт, профиль и источник | «Бот и системные события дают контекст; оцениваем действия оператора. Это результат прогона [ID], модель [из интерфейса], версия [из интерфейса]». Для mock: «Сейчас демонстрируем интерфейс на условной оценке». |
| **1:00–1:35** · 35 с | Критерий → пояснение → ссылка на доказательство | «Ни одного балла без доказательства — наш принцип проверяемости. Ссылка ведёт к исходной реплике; код проверяет цитату и её границы. Это не гарантирует правильность смыслового вывода». |
| **1:35–2:10** · 35 с | Подготовленный звонок → цитата → плеер; короткий фрагмент | «У звонка есть транскрипт и запись. Таймкод учитывает начало и паузы записи. Дикцию и интонацию по одному тексту мы не оцениваем». При недоступном аудио сразу перейти к запасному пути. |
| **2:10–2:35** · 25 с | Вернуться к чату → N/A и причина; для пропущенного действия — проверенный участок | «N/A означает, что условие критерия не наступило. Когда нужного действия нет, показываем участок, который проверили, а не придумываем цитату отсутствующего действия». |
| **2:35–3:00** · 25 с | Итог, вклад критериев, грубая ошибка отдельно | «Шкала переводится в долю веса. N/A исключается из знаменателя, итог считает код. Грубая ошибка — отдельный флаг; неполная оценка не превращается в подтверждённый полный результат». |
| **3:00–3:20** · 20 с | Роль «Оператор» → критерий → апелляция → комментарий → отправить | «Оператор оспаривает конкретный критерий и объясняет почему. Обращение сохраняется вместе с исходным ответом и версией правила». |
| **3:20–3:45** · 25 с | «Проверяющий» → «На проверке» → обращение → доказательство → новый ответ и причина → «Изменить…» | «Теперь отдельное действие проверяющего. Он сопоставляет правило и реплики, указывает причину и сохраняет решение». Обоснованный кейс выбрать до защиты; не менять верный ответ ради красивого числа. |
| **3:45–4:00** · 15 с | Исходный ответ → решение → новый итог → история | «Исходная оценка остаётся в истории; итог пересчитан по решению. Здесь видно, что изменилось и почему». При подтверждении сказать, что итог не изменился. |
| **4:00–4:20** · 20 с | «Чек-лист» → новая версия → заменить текст критерия → причина → «Сохранить как v…» | «Правило меняется через интерфейс. Хеш содержания отличает новую формулировку; старый ответ к ней не подходит». |
| **4:20–4:40** · 20 с | Выбрать контрольный набор → «Применить v… к диалогам» → табло «Оценка» (запуск сразу, отдельного подтверждения нет) | «Запустили расчёт изменённого критерия. Неизменившиеся ответы могут переиспользоваться; новым диалогам нужна полная оценка. На табло видны состояние и вызовы». Начавшийся прогон не называть завершённым. |
| **4:40–5:00** · 20 с | «Качество» → источник, выборка, пропуски, машинный эталон | «На повторно использованном DEV получено 152 совпадения из 159 размеченных ответов. Девять ответов без эталона показываем отдельно. Независимую точность на контроле назовём после проверки организаторами». |

**Запуск сервера для защиты:** `CQA_RUN_WORKERS=10 python -m uvicorn server:app --host 127.0.0.1 --port 8000` — замена критерия на 10 диалогах идёт одной волной вызовов (по умолчанию 8 = две волны). Применять замену к ≤10 диалогам.

**Если расчёт не завершился до 4:40:** показать реальный статус и перейти к «Качеству». Реплика: «Задача выполняется; это ещё не готовый результат. После завершения покажем его отдельно». Не подменять результат новой версии старой оценкой.

## Запасной путь при сбое сети

На диагностику во время выступления — не более 10 секунд. Таймкипер сохраняет исходные границы блоков; при задержке сокращаем вступление к звонку, а не обязательные N/A, решение и изменение критерия.

1. **API недоступен, сохранённый результат доступен.** Сказать: «Это сохранённый результат прогона [ID], не свежая оценка». Показать цитату, формулу и историю; новая оценка потребует восстановления связи. Кэш не доказывает способность оценить новый диалог.
2. **Не открывается запись звонка.** Показать транскрипт, исходный таймкод и кнопку записи: «Ссылка на звук сейчас недоступна; успешное прослушивание не подтверждаем». При наличии заранее проверенной разрешённой локальной записи включить её и назвать источник; иначе продолжить без звука.
3. **Недоступен весь сервис.** Включить только реально подготовленное и проверенное резервное видео, назвав дату и версию. Если видео нет, открыть `docs/architecture.svg` и честно назвать непоказанные шаги; схема и mock не являются работающим API.
