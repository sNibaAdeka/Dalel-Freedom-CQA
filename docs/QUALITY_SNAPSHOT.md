**стоимость — по ценам моделей в каждом вызове; токены по моделям не разделены**. Используем сохранённый `cost_kzt_full`: llm считает цену вызова, evaluator распределяет её между критериями, каскад суммирует стадии. Общий итог строки проверяется, а не добавляется повторно. Это reported usage estimate, не счёт и не гарантия полного исторического учёта.

**Исправление предыдущего W8-аудита:** отсутствие разбивки токенов не делает сохранённую сумму стоимости неизвестной. Вывод о полностью неизвестной стоимости каскада был чрезмерным. Нулевые сохранённые цены при ненулевых платных токенах показаны отдельно и означают нижнюю оценку/неполный учёт. Из объединённых токенов нельзя подтвердить или опровергнуть покрытие цены каждой стадии; у каскада/маршрутизации это остаётся неизвестным. Подтверждённый коэффициент экономии по несопоставимым источникам не выводится.

Конверсия сохранённых тенге в USD использует `config/models.json:usd_kzt` = 500.0; курс на момент запуска в slim JSONL не записан, поэтому это явное допущение. `cost_audit.token_price_estimate` хранит отдельный сценарий текущих цен только для однозначных моделей; его нельзя смешивать с исторической ценой другого профиля. Wall time включает локальный evaluator; состояние кэша отдельно выведено из charged/full cost, а не из явного флага JSONL.

## Источники для экономики банка

Доля ручной проверки вычисляется только по финальному `needs_review`: хотя бы один критерий помечен. Эскалация в Gemini не равна направлению человеку. При пропущенных флагах доля неизвестна. Стоимость пары — амортизированная цена запланированного критерия, не предельная цена изменения одного критерия.

- cloud: сохранённые model labels показывают Gemini в 21/21 диалогов, эскалацию в 0, прямой маршрут звонка в 0. Кэш: unknown. Это не полная телеметрия всех provider calls.
- cascade: сохранённые model labels показывают Gemini в 9/21 диалогов, эскалацию в 9, прямой маршрут звонка в 0. Кэш: mixed. Это не полная телеметрия всех provider calls.
- routing: сохранённые model labels показывают Gemini в 10/21 диалогов, эскалацию в 8, прямой маршрут звонка в 2. Кэш: cached. Это не полная телеметрия всех provider calls.

В таблице показано записанное wall time. Для cached/mixed/unknown скорость живого расчёта и её проекция на большой объём остаются неизвестными; калькулятор получает null вместо ложной скорости из кэша.

Локальный Ollama: внешняя API-плата отсутствует по конфигурации; оборудование, электроэнергия и доля ручной проверки не измерены. Качество и время измерены на holdout: 62,3% (ниже константы 83,0%), 341 с на диалог в свежем офлайн-прогоне — только офлайн-резерв.

ДИ групп с менее чем двумя информативными диалогами не выводится. Малые языковые и канальные подвыборки не подтверждают обобщение на новые диалоги. Сценарии/переводы могут зависеть друг от друга: кластеризация по диалогу не устраняет эту зависимость. MAE использует только полные пары всех критериев, N/A перераспределяет веса; критический флаг не добавляет баллы.

## Воспроизведение

```sh
python scripts/quality_report.py --source-root /path/to/w-int --legacy-root /path/to/w-m1 --references-root /path/to/agents/reports
python -m pytest -q tests/test_quality_report.py
```

SHA256 входов записаны в `quality.json`: `methodology.inputs`, `report.source.sha256`, `report.reference.sha256`. Полные JSONL, цитаты и ID реплик в отчёт не попадают. Два запуска при неизменных входах дают одинаковые JSON и Markdown.
